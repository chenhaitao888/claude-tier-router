# Claude Code 双模型路由设计

本项目以 Go 实现 Claude Code 本地网关，在用户提供的 Opus 与 DeepSeek Flash 两组 Anthropic Messages 接口之间逐请求评估路由。目标是在任务验收质量达到要求时，降低整个任务的总成本。第一期仅适配 Claude Code，不依赖 Together 服务。

## 产品范围

使用一个本地进程提供代理、路由、SQLite 存储和统计页面。启动器只修改子进程环境。密钥可直接写入被 Git 忽略的本地 config.json，也兼容环境变量；配置中的非空密钥优先。上游密钥不写入日志或统计数据库。本地网关与统计页免凭证；启动器只为 Claude Code 的认证参数提供固定占位值。监听限制为 loopback，接口检查 Host 与浏览器来源。固定高级、固定廉价、观察和自动四种模式用于接入验证、对照和逐步上线。观察模式仍由高级模型执行，但记录推荐路由。

每个推理请求都评估，不代表每个请求都必须切换。能力限制、历史兼容性、缓存收益和分类不确定性均可能使最终模型与分类推荐不同。客户端 token counting 不触发分类器，也不算推理请求。

## 请求流程

1. 校验本机来源、请求大小和结构，关联会话、用户提示、代理及请求类别。
2. 检查上下文及内容块的兼容性，提取当前任务文本和近期工具错误。
3. 本地规则处理明确场景；历史或能力已锁定候选时跳过付费分类器；其余不确定请求的可选 Flash 分类器只读取去除系统提醒的有界任务和上下文，独立调用上游并单独记账。分类器结果是启发式建议，其置信度未经概率校准。
4. 为两个候选模型估计本次输入、缓存读取或写入、输出费用，比较切换收益。
5. 根据运行模式、质量建议及历史兼容约束决定实际模型，记录理由。
6. 只改写顶层 model 和上游身份认证，保留其余请求内容；SSE 原样实时转发。
7. 记录完整或中断结果、usage、价格快照、成本状态与耗时。对失败和不完整调用不能假定免费。

网关不执行模型返回的工具，不重放有副作用的工具。一次响应开始后不拼接其他模型输出。初版不在代理内自动重试，避免与 Claude Code 的重试叠加；每次客户端重试仍形成独立请求记录。

## 路由策略

| 场景 | 初始建议 |
| --- | --- |
| 明确的短解释、文本整理、局部简单修改 | Flash |
| 复杂故障定位、跨模块设计、并发和约束冲突 | Opus |
| 当前工具结果存在失败信号 | 保守使用 Opus，并记录为信号而非质量结论 |
| 分类器失败或信息不足 | 保留当前兼容模型或 Opus |
| 受保护的 thinking 或服务端状态历史 | 保留已知模型；未知来源需明确固定模型 |
| 价格未知或不同币种且未配置汇率 | 按能力建议选择；记录无法比较金额，仍统计使用占比 |

规则与提示词需要用真实工作任务持续校准，不能仅凭文本长度决定能力。首次实现的词表属于可检查的起点，不是训练好的复杂度分类模型。测试失败可能由环境或权限造成，必须由评估层进一步归因。

自动切换默认关闭跨模型文本历史接续。完成实际接口验证后，可打开 allow_text_switch；这一开关只放行普通文本和客户端工具历史。thinking、redacted_thinking、服务端工具等未知兼容状态仍锁定来源。恢复会话时若无法确定这些块的来源，自动模式返回明确错误，不静默删除历史。

## 缓存与价格

Opus 与 Flash 独立维护缓存估计，缓存不会跨模型迁移。保留每条分支在每个模型上的历史前缀，切回原模型时可估计仍存活的前缀。状态按会话、代理和请求类型隔离，辅助请求再按提示隔离，避免并行子代理相互改变模型。

缓存状态是进程内的预测，不是供应商命中承诺。重启后按冷缓存估计；真实 usage 用于记录观测和校正。v4 使用工具、系统及消息内容块级前缀，成功响应的 usage 校准缓存覆盖量；自动缓存把冷输入也纳入预测，显式缓存只使用断点及回看范围。覆盖量按相对大小分摊并打八折，限制条目数量和本地存活时间。DeepSeek TTL 配置表示保守预测窗口，不是其服务端固定 TTL。

费用按以下互不重叠的计费项核算：

普通输入 + 缓存读取 + 五分钟缓存写入 + 一小时缓存写入 + 输出。

所有单价以 USD 或 CNY 每百万 tokens 表示，保存版本与发出请求时选定的价格快照。不同币种分别汇总；可选 `policy.exchange_rate` 提供用户指定的 CNY/USD 固定比值和版本，只用于路由候选费用折算，快照随决策持久化。未配置时不比较不同币种金额。配置空价格表示未知。显式写入有 tokens 但无 TTL 细分时不猜测写入价格。服务端工具额外计费未配置时，总费用保持未知。高峰/空闲价按配置的时区、星期、时间窗和假期日历选择，记录选中时段和版本；日历覆盖范围以外保持未知。修改配置后重启生效。阶梯及中转倍率尚需后续适配。

Anthropic 兼容接口不等于计费语义完全相同。接入前必须核实上游 input_tokens 是否排除缓存项，以及价格和账单。初版支持文档规定的 Anthropic 分离计数契约，不自动套用 OpenAI 的 inclusive prompt_tokens。

预测采用字节与字符保守估算，输出使用配置的先验值，均明确标为估计。切换门槛避免小幅收益导致频繁切换；冷启动已计入输入或写入费用，不重复加切换费用，也不把已发生费用当作未来成本。

## 统计与评估

数据库存储请求、分类器调用和人工任务反馈。v4 对已识别的危险工具分类器 v1 上下文只在本地指纹和输入估算中排除，转发内容保持不变；未知字段和版本仍严格参与指纹。逐档保存缓存失配原因与分层变化计数，内容哈希只留在内存。请求持有推荐模型、候选成本、实际模型、理由、策略版本、价格版本、usage、HTTP 状态、完整性和耗时。默认不持久化提示词、响应正文、密钥或工具参数。显式启用 `store_task_summaries` 后，可在独立的 `task_labels` 表保存每次用户提问前 80 个字符，去除系统提醒，首次写入后不随中间调用覆盖。按完整会话 ID 与提问 ID 聚合问题，评价入口只设在问题行；表单展示固定的目标问题与关联标识。历史补齐仅使用精确 ID 匹配，无法识别的历史问题先由用户命名。分类诊断仅保存状态、结构校验原因、停止原因与长度。离线复查可以使用单独提供的本地请求样本，不写回原账本；不能从只有 usage 的记录反推请求。

本地页面提供总览、最近请求、任务分组、完整决策详情与人工通过/失败/未知反馈。HTTP 成功及 SSE 正常结束仅表示传输完整，不代表任务质量。用户验收与自动测试证据需要分别标明来源，不能把模型自评当作事实。当前提供三类版本化人工证据清单，服务端检查每项结果和证据并推导总结果；缺证据不能通过，未运行的测试保持未知。此清单不自动执行测试或调用模型。

主要产品指标为任务验收率和每个成功任务的总成本。页面提供人工验收数量、分币种已记录费用和单独标注的历史估算，以及不依赖价格的请求次数占比与 token 占比；在存在未知费用、未评估任务或缺失任务关联时，不展示伪精确成功任务成本或节省率。

节省率需要区分价格模拟和完整任务对照。对照应从同一代码快照分别运行 all_opus、all_flash、auto，分离工作目录和缓存条件，重复抽样并包含分类、重试、返工及评估费用。单步双模型回答只能评价单步，不能证明整项任务收益。评估模型打分为辅助，验收测试和人工评审为主要证据。

## 实施与验收

| 阶段 | 交付与验证 |
| --- | --- |
| 接入 | 双上游、认证替换、模型映射、未知字段保留、SSE、取消、错误转发 |
| 记录 | SQLite 持久化、分类开销、usage 去重、缺失值、价格快照、手工反馈 |
| 路由 | 规则、可选分类器、观察模式、缓存估算、兼容锁定 |
| 联调 | 真实两接口的普通对话、工具、thinking、压缩、恢复和长上下文 |
| 质量验证 | 代表性任务集三策略对照，达到约定质量后评估成本收益 |

必须测试 Opus → Flash 与 Flash → Opus 两个方向。检查工具结果 ID 匹配、thinking 历史、流中断、价格缺失及并行分支。真实测试需要用户在本地配置密钥和准确模型 ID；模拟上游的成功不能替代真实模型质量验证。

## 后续扩展

增加测试与构建结果采集 hooks、离线任务重放、抽样对照实验、成功任务成本与置信区间、价格版本生效日期、供应商账单对账以及更精细的缓存预测校准。第二阶段再考虑更多客户端和模型，不在第一期引入多租户、分布式队列或模型训练。

## 本地访问与分页

网关不生成、打印或校验本地凭证，旧配置的网关凭证字段仅作兼容读取并丢弃。上游认证仍使用对应 provider 的密钥，客户端占位值不会转发。

问题列表和请求明细均使用服务端分页，支持每页 10、20、50 条，默认 20。任务统计在完整账本上聚合后分页，请求明细在同一 SQLite 读事务内计数并按稳定顺序取页。精确问题筛选使用完整 session_id + prompt_id。页面中的验收目标与分页独立，翻页不切换评价对象。
