# Claude Code 双模型路由设计

本项目以 Go 实现 Claude Code 本地网关，在用户提供的 Opus 与 DeepSeek Flash 两组 Anthropic Messages 接口之间逐请求评估路由。目标是在任务验收质量达到要求时，降低整个任务的总成本。第一期仅适配 Claude Code，不依赖 Together 服务。

## 产品范围

使用一个本地进程提供代理、路由、SQLite 存储和统计页面。启动器通过子进程环境和临时会话设置指定本地连接，不改写全局或项目配置。密钥可直接写入被 Git 忽略的本地 config.json，也兼容环境变量；配置中的非空密钥优先。上游密钥不写入日志或统计数据库。本地网关与统计页免凭证；启动器只为 Claude Code 的认证参数提供固定占位值。监听限制为 loopback，接口检查 Host 与浏览器来源。固定高级、固定廉价、观察和自动四种模式用于接入验证、对照和逐步上线。观察模式仍由高级模型执行，但记录推荐路由。

每个推理请求都评估，不代表每个请求都必须切换。能力限制、历史兼容性、缓存收益和分类不确定性均可能使最终模型与分类推荐不同。客户端 token counting 不触发分类器，也不算推理请求。

## 请求流程

1. 校验本机来源、请求大小和结构，关联会话、用户提示、代理及请求类别。
2. 检查上下文及内容块的兼容性，提取当前任务文本和近期工具错误。
3. 本地规则处理明确场景；历史或能力已锁定候选时跳过付费分类器；其余不确定请求的可选 Flash 分类器只读取去除系统提醒的有界任务和上下文，独立调用上游并单独记账。分类器结果是启发式建议，其置信度未经概率校准。
4. 为两个候选模型估计本次输入、缓存读取或写入、输出费用，比较切换收益。
5. 根据运行模式、质量建议及历史兼容约束决定实际模型，记录理由。
6. 只改写顶层 model 和上游身份认证，保留其余请求内容；SSE 原样实时转发。
7. 记录完整或中断结果、usage、价格快照、成本状态与耗时。对失败和不完整调用不能假定免费。

网关不执行模型返回的工具，不重放有副作用的工具。一次响应开始后不拼接其他模型输出。初版不在代理内自动重试，避免与 Claude Code 的重试叠加；每次客户端重试仍形成独立请求记录。

## 路由策略

| 场景 | 初始建议 |
| --- | --- |
| 明确的短解释、文本整理、局部简单修改 | Flash |
| 复杂故障定位、跨模块设计、并发和约束冲突 | Opus |
| 当前工具结果存在失败信号 | 保守使用 Opus，并记录为信号而非质量结论 |
| 分类器失败或信息不足 | 保留当前兼容模型或 Opus |
| thinking 历史且 auto 命中本地复杂任务或内容能力规则 | 优先 Opus；保留原始历史并记录越过限制的理由 |
| 其他受保护历史，或普通任务的 thinking 历史 | 保留已知模型；未知来源需明确固定模型 |
| 价格未知或不同币种且未配置汇率 | 按能力建议选择；记录无法比较金额，仍统计使用占比 |

规则与提示词需要用真实工作任务持续校准，不能仅凭文本长度决定能力。首次实现的词表属于可检查的起点，不是训练好的复杂度分类模型。测试失败可能由环境或权限造成，必须由评估层进一步归因。

自动切换默认关闭跨模型文本历史接续。完成实际接口验证后，可打开 allow_text_switch；这一开关只放行普通文本和客户端工具历史。auto 下本地 `complexity_rule` 或 `content_requires_high_capability` 命中后，若保护原因仅有 thinking / redacted_thinking，则直接使用高级模型，即使来源未知或 allow_text_switch 关闭也允许升级；不调用分类器，仍检查高级模型上下文限制。普通任务、工具失败信号、模型分类结论和服务端工具等其他状态继续使用原历史约束。固定模式不受此例外影响。auto 不能借助同源受保护历史放行 Flash 不支持的 image / document / search_result；当服务端状态锁定来源 Flash 且又需要高级内容能力时，返回 409 而不派发。

该例外只改变路由优先级，不删除或重写 thinking、签名、工具调用和结果。上游对异源历史的兼容性必须单独验证；拒绝时透传错误并记入失败记录，不自动降级或付费重试。请求详情记录 `complexity_overrides_thinking` / `capability_overrides_thinking` 和 `routing_version`，可与旧策略记录区分。

## 缓存与价格

Opus 与 Flash 独立维护缓存估计，缓存不会跨模型迁移。保留每条分支在每个模型上的历史前缀，切回原模型时可估计仍存活的前缀。状态按会话、代理和请求类型隔离，辅助请求再按提示隔离，避免并行子代理相互改变模型。

缓存状态是进程内的预测，不是供应商命中承诺。重启后按冷缓存估计；真实 usage 用于记录观测和校正。v4 使用工具、系统及消息内容块级前缀，成功响应的 usage 校准缓存覆盖量；自动缓存把冷输入也纳入预测，显式缓存只使用断点及回看范围。覆盖量按相对大小分摊并打八折，限制条目数量和本地存活时间。DeepSeek TTL 配置表示保守预测窗口，不是其服务端固定 TTL。

费用按以下互不重叠的计费项核算：

普通输入 + 缓存读取 + 五分钟缓存写入 + 一小时缓存写入 + 输出。

所有单价以 USD 或 CNY 每百万 tokens 表示，保存版本与发出请求时选定的价格快照。不同币种分别汇总；可选 `policy.exchange_rate` 提供用户指定的 CNY/USD 固定比值和版本，只用于路由候选费用折算，快照随决策持久化。未配置时不比较不同币种金额。配置空价格表示未知。显式写入有 tokens 但无 TTL 细分时不猜测写入价格。服务端工具额外计费未配置时，总费用保持未知。高峰/空闲价按配置的时区、星期、时间窗和假期日历选择，记录选中时段和版本；日历覆盖范围以外保持未知。修改配置后重启生效。阶梯及中转倍率尚需后续适配。

Anthropic 兼容接口不等于计费语义完全相同。接入前必须核实上游 input_tokens 是否排除缓存项，以及价格和账单。初版支持文档规定的 Anthropic 分离计数契约，不自动套用 OpenAI 的 inclusive prompt_tokens。

预测采用字节与字符保守估算，输出使用配置的先验值，均明确标为估计。切换门槛避免小幅收益导致频繁切换；冷启动已计入输入或写入费用，不重复加切换费用，也不把已发生费用当作未来成本。

## 统计与评估

数据库存储请求、分类器调用和人工任务反馈。v4 对已识别的危险工具分类器 v1 上下文只在本地指纹和输入估算中排除，转发内容保持不变；未知字段和版本仍严格参与指纹。逐档保存缓存失配原因与分层变化计数，内容哈希只留在内存。请求持有推荐模型、候选成本、实际模型、理由、策略版本、价格版本、usage、HTTP 状态、完整性和耗时。默认不持久化提示词、响应正文、密钥或工具参数。显式启用 `store_task_summaries` 后，可在独立的 `task_labels` 表保存每次用户提问前 80 个字符，去除系统提醒，首次写入后不随中间调用覆盖。按完整会话 ID 与提问 ID 聚合问题，评价入口只设在问题行；表单展示固定的目标问题与关联标识。历史补齐仅使用精确 ID 匹配，无法识别的历史问题先由用户命名。分类诊断仅保存状态、结构校验原因、停止原因与长度。离线复查可以使用单独提供的本地请求样本，不写回原账本；不能从只有 usage 的记录反推请求。

本地页面提供总览、最近请求、任务分组、完整决策详情与人工通过/失败/未知反馈。HTTP 成功及 SSE 正常结束仅表示传输完整，不代表任务质量。用户验收与自动测试证据需要分别标明来源，不能把模型自评当作事实。当前提供三类版本化人工证据清单，服务端检查每项结果和证据并推导总结果；缺证据不能通过，未运行的测试保持未知。此清单不自动执行测试或调用模型。

主要产品指标为任务验收率和每个成功任务的总成本。页面提供人工验收数量、分币种已记录费用和单独标注的历史估算，以及不依赖价格的请求次数占比与 token 占比；在存在未知费用、未评估任务或缺失任务关联时，不展示伪精确成功任务成本或节省率。

节省率需要区分价格模拟和完整任务对照。对照应从同一代码快照分别运行 all_opus、all_flash、auto，分离工作目录和缓存条件，重复抽样并包含分类、重试、返工及评估费用。单步双模型回答只能评价单步，不能证明整项任务收益。评估模型打分为辅助，验收测试和人工评审为主要证据。

## 实施与验收

| 阶段 | 交付与验证 |
| --- | --- |
| 接入 | 双上游、认证替换、模型映射、未知字段保留、SSE、取消、错误转发 |
| 记录 | SQLite 持久化、分类开销、usage 去重、缺失值、价格快照、手工反馈 |
| 路由 | 规则、可选分类器、观察模式、缓存估算、兼容锁定 |
| 联调 | 真实两接口的普通对话、工具、thinking、压缩、恢复和长上下文 |
| 质量验证 | 代表性任务集三策略对照，达到约定质量后评估成本收益 |

必须测试 Opus → Flash 与 Flash → Opus 两个方向。检查工具结果 ID 匹配、thinking 历史、流中断、价格缺失及并行分支。真实测试需要用户在本地配置密钥和准确模型 ID；模拟上游的成功不能替代真实模型质量验证。

## 本地访问与分页

网关不生成、打印或校验本地凭证，旧配置的网关凭证字段仅作兼容读取并丢弃。上游认证仍使用对应 provider 的密钥，客户端占位值不会转发。

问题列表和请求明细均使用服务端分页，支持每页 10、20、50 条，默认 20。任务统计在完整账本上聚合后分页，请求明细在同一 SQLite 读事务内计数并按稳定顺序取页。精确问题筛选使用完整 session_id + prompt_id。页面中的验收目标与分页独立，翻页不切换评价对象。

## 启动配置优先级

`install.sh` 将源码编译至项目 `bin/router`，并在用户 `~/.local/bin` 建立同名链接。安装只为缺少 PATH 的 zsh / bash 追加命令搜索路径，不复制或改写模型配置及数据库；遇到其他已有命令文件则停止。支持自定义命令目录和跳过 PATH 更新。

省略 `-config` 时先解析可执行文件的真实路径：位于 `bin` 目录则先查找其父目录 `config.json`，再查找可执行文件同目录、用户 `~/.config/claude-tier-router/config.json`、当前目录 `config.json`。第一个已存在的配置异常时直接报错，不悄悄换用其他配置。显式 `-config` 优先，路径相对调用目录解析。启动不切换工作目录，Claude Code 使用调用者的业务项目目录，数据库相对配置文件目录解析；启动日志显示实际配置路径。

普通 Claude Code 设置中的 env 能覆盖启动环境，因此启动器同时传入会话级 `--settings`。仅覆盖网关地址、认证占位值、模型别名、归属请求头和上下文窗口，并清空本次会话的旧 provider 认证/helper/云开关。其他设置照常加载，managed policy 保持客户端自身的优先级。

用户额外指定的单个 `--settings` 支持文件与 JSON，在内存合并后写入权限 0600 的临时设置文件，避免将其可能含有的内容放入进程命令行。正常退出清理临时目录；原设置文件不写回。验收以 `/status` 的实际地址和 Router 新增请求记录为准。

## 诊断范围与运行配置

每次创建网关生成唯一运行标识，推理和分类账本同时记录它。本次启动的诊断按运行标识查询，不使用时间窗口猜测归属，可区分同一数据库的重启与并行网关。旧记录不回填，保留在全部历史。当前生效配置独立于历史计数显示，避免旧的跳过原因被误认作当前配置。

分类状态与规则原因使用独立标签，`uncertain` 在分类统计中表示分类器不确定或置信不足。缓存诊断提供未计入比较的原因计数，未知用量仍保持未知；费用、任务和反馈的完整账本统计不受诊断筛选影响。

## 请求归属与账单排查

问题列表按完整 session_id + prompt_id 聚合；没有问题 ID 或只有后台调用的独立组不进入问题列表。请求明细独立展示 request_class 和问题归属，“未关联”不等于“后台”。核对同一时段的费用须查看全部请求；问题行的高级模型零调用不能代表该时段网关高级模型零调用。模型列明确标注推荐和实际执行，分类器只显示执行模型，避免把两档位误解为两次调用。

## 上下文超限与客户端恢复

客户端 `router-auto` 的上下文容量通过 `CLAUDE_CODE_MAX_CONTEXT_TOKENS` 与两档配置的较小值对齐，自动压缩窗口仍为其 75%。自动压缩的用户开关和禁用环境变量继续由 Claude Code 处理。

路由预检查将内容能力冲突、输出预算配置错误、估算上下文超限分开。每个决策保存 `context_budget`：估算输入、预留输出、合计、两档配置容量和估算方法。容量均标注 configured，输入仍是排除已识别元数据后的保守字节估算，不能作为真实 token 计数。

仅 `selected_model_context_limit` 返回 Anthropic 格式的 HTTP 400 / invalid_request_error，消息包含 prompt is too long，并明确标注 Router 本地估算。Claude Code 可识别这一错误并尝试压缩恢复。输出预算本身大于等于配置窗口时返回 output_budget_exceeds_context（400），不使用提示过长信号；内容能力冲突返回 selected_model_content_unsupported（409），也不触发不必要的压缩。历史来源错误仍使用原语义。错误响应带请求 ID，账本保存实际 HTTP 状态、诊断与未派发状态。

此变化只改进本地预检查的错误表达，不伪造上游计数、不删除历史、不自动调用模型重试，也不改写供应商返回的错误。由 Claude Code 发起的压缩请求仍走正常代理和计费记录。

## 多会话共享网关

`router claude` 自动连接同配置的本地共享网关；没有服务时启动独立后台进程，后续窗口复用监听端口和 SQLite。后台进程脱离启动终端的会话，使用独立标准输入和权限 0600 的日志文件。关闭首个 Claude 不会结束网关；业务工作目录仍由各自启动器保留，Claude 会话标识继续用于分支和任务隔离。

启动器以持有的本地 HTTP 连接登记活动会话。正常结束、终端关闭或进程退出会释放连接，无需永久 PID 注册；控制器同时统计在途推理请求。Ctrl+C 由同一前台进程组的 Claude 处理，启动器保留登记；终止信号转交所属 Claude 子进程。共享服务自身不依赖任何启动器的生命周期。

服务协议标识和 run_id 用于确认端点；连接时校验包含实际解析密钥的配置摘要及可执行文件摘要。摘要仅在本地校验，不在公开状态接口或日志输出，不新增用户需要填写的凭证。配置和程序变化时，仅自动替换没有活动会话和请求的后台服务；前台 serve 进程由用户管理。不同配置使用同一端口且有活动会话时拒绝混用，避免把请求交给另一套账户或策略。

数据库目录内的私有锁文件串行化服务启动；只有绑定成功的进程打开数据库、发布原子运行状态文件。并发启动和端口 0 均复用胜出的进程。控制请求沿用网关的 loopback Host / Origin 检查，过期 run_id 无法停止新进程。旧版或非 Router 服务占用端口时报告冲突，不终止或复用该进程。

`router status` 查询活动会话与在途请求；`stop`、`restart` 默认拒绝中断使用中的服务，显式 `-force` 才执行中断。首次从内嵌网关版本升级需先结束旧进程。运行状态和日志不包含密钥，数据库与历史记录保留。
