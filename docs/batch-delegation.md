# 重复工具工作与执行委派

适用于 `router claude --cooperate`。现场的取数任务暴露了一个更一般的问题：模型可以认同分工方案，随后仍在主会话里逐批执行。升级后，Router 能在客户端实际准备运行工具时给出交接信号。高级模型保留口径、设计和验收，Executor 可以接手已有计划的重复步骤。

## 默认行为

| 高级主会话实际发出的工具 | 同一提问内，首次遇到不同于首批的参数 |
| --- | --- |
| 任意 MCP 服务的 `ai_query_submit`、`query_submit` | 暂停本次模型回复中的新批次，提示把剩余分批工作、已提交作业的 ID、轮询频率和验收条件交给前台执行者 |
| `Grep`、`Glob` | 照常执行并提醒一次。下一步可能要根据证据判断，主会话可以继续检索 |
| 结果轮询、普通读取、Shell、写入及其他未配置工具 | 沿用 Claude Code 原有的工具流程 |

每个具体工具在每个问题里分别计数，包括 MCP 服务名。同一份参数的首批重试仍可通过，判断时会规范化 JSON 对象的键顺序。并行提交由 SQLite 事务预留一个探查名额。触发暂停后，如果还有分析要做、用户要求直接处理或委派失败，主会话可以在**下一次模型回复**继续操作。同一工具调用重复投递 hook 时会收到原决定。统计中的首批表示客户端尝试调用，工具是否成功以实际结果为准。

Router 核对模型回复里的调用 ID、会话、工具和所属问题。hook 缺少问题 ID 时也可使用唯一关联；冲突、丢失、子代理、普通会话和直接使用低档的请求均沿用原流程。Agent 工具不可见时允许主会话继续。此检查只会添加上下文或暂时拒绝本次调用，工具权限仍由 Claude Code 执行。委派账本保存调用标识、工具名、首批参数摘要和状态。参数原文、查询结果和完整提示不会写入该账本。

在「我的问题 → 协作详情」看某个工具是否提示过交接、后续主会话是否继续调用，以及该问题实际出现的执行子代理和执行阶段高低档请求数。一次提示不能证明子代理已经运行。相同问题内可能有多个子任务，页面不会把某个子代理自动归功于某条提示。

## 配置其他工作

`cooperation.batch_tools` 省略时使用上表，显式对象替换整张规则表，空对象关闭工具检查。可按工具精确匹配，或使用 `mcp__*__方法名` 匹配不同服务的同一方法，精确名称优先。以下配置保留默认规则，并加入文档渲染工具。

```json
{
  "cooperation": {
    "batch_tools": {
      "mcp__*__ai_query_submit": "handoff",
      "mcp__*__query_submit": "handoff",
      "Grep": "suggest",
      "Glob": "suggest",
      "mcp__docs__render_page": "handoff"
    }
  }
}
```

`handoff` 适合可以独立提交的批次，`suggest` 适合下一步可能依赖当前结果的探索。一个作业只有轮询、不同参数实际表示同一业务项、一个工具封装许多批次，都会影响这个信号。Router 无法只凭工具参数判断任务是否可委派。按整题验收、耗时、主会话及执行者的实际调用、缓存和已核算成本检验效果；价格缺失时优先比较调用和用量。

## 独立编排入口的可行性评估

**在 Go CLI 增加可选择的独立入口可行。** 适用场景是已经能写出清晰执行合同，且要求主模型即使没有调用 Agent，执行者也能按计划启动。现有网关掌握模型消息和账本，交互式 Claude Code 掌握工具、MCP 连接、工作目录和交互权限。应由单独的命令拥有任务生命周期。Go 可以通过 `claude -p` 启动新的执行进程、读取结构化输出，再为高级模型提供可核对的回报。这里的入口仅为设计建议。[Claude Code 非交互运行说明](https://code.claude.com/docs/en/headless) · [Claude Code 工具钩子](https://code.claude.com/docs/en/hooks)

| 环节 | 最小实现与验收条件 |
| --- | --- |
| 计划和归属 | 高档返回可验证的合同，包含任务 ID、已确定的口径、允许的数据源、工具、工作目录、产物、预算和验收条件。Router 在派发前校验并持久化状态。跨进程显式关联根任务和步骤，同一会话里相邻的请求不能代替父子关系。 |
| 执行宿主与权限 | 由用户启动的 CLI 在指定目录运行低档 Claude Code，显式限定工具与 MCP 配置，在本地确认证书、凭据和组织策略兼容。交互会话的一次授权不能充当新进程授权。缺少必要授权或工具时回到等待人工处理。 |
| 恢复、取消与费用 | 为每步分配唯一 ID，限制并发、调用数、时间和重试。重启后先核对已有作业与产物。未知状态的外部写入、作业提交等不能盲重试。取消要同时处理执行进程和仍在数据源运行的作业。 |
| 结果与判断 | 执行者返回证据引用、确定性检查和未决项。高级模型复核必要的项目，剩余仅排版时沿用低档交付。看板把规划、执行、重试、复核计入同一任务，并单列人工验收。 |

建议先做一个只读、串行、仅使用合成或已授权输入的原型，对比当前协作模式。验收至少覆盖主模型不调 Agent、执行者权限不足、进程中断恢复、取消和重复提交。只有在正确率相当且整题成本、延迟或派发可靠性有可复现改善时，再扩大到有副作用的工具。独立会话要重新提供必要上下文，缓存也可能重建，小任务有可能更贵。

## 本地验证

真实 Claude Code 2.1.329 连接回环模拟模型，五组场景覆盖标识符检索、文档交付、代码修改、执行者交回设计和批次交接。批次用例显式配置 `Read: handoff`，验证主会话读取首个文件、收到第二个调用的拒绝理由，随后执行子代理读取第二个文件。该用例共 6 次模型请求，执行者占 2 次。Go 回归另覆盖查询提交、代码检索、文档渲染、并发与重复投递、非流式回复、问题归属冲突和 Agent 缺失。运行 `go test -race ./...`，构建 `bin/router` 后可运行 `python3 scripts/validate_cooperation.py`。这些测试使用合成数据；实际模型的委派率和整题收益仍需现场样本。
