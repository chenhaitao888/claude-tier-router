# 协作模式验证

验证日期：2026-11-20。Claude Code 2.1.329，macOS，Router 的 cooperation-v1。

## 验证方式

`scripts/validate_cooperation.py` 启动真实 Claude Code 和 Router，使用隔离的 Claude 配置、独立临时工作目录、SQLite 和 loopback 模拟上游。上游按固定脚本返回工具调用与结果，不使用真实模型。代码、表格和报告都是合成样本；没有调用付费 API。

这验证了客户端、路由、工具、hook 和统计的完整接线，不验证模型自主拆解任务、遵守合同或判断质量的能力。

## 实际结果

| 用例 | 主会话 Opus 档请求 | Flash 执行请求 | Opus 档验收请求 | 结果 |
| --- | --- | --- | --- | --- |
| 三行 CSV 生成文档 | 4 | 3 | 2 | 生成的文档行数和总数正确；角色、问题归属一致 |
| 局部修改 Go 函数 | 3 | 4 | 2 | 执行子代理修改函数并调用测试；外部独立运行同一测试也通过 |
| 执行遇到缺失口径 | 2 | 1 | 0 | 记录 needs_design，交回主会话，未标成人工通过 |

“Opus 档”和“Flash”表示 Router 的 high/low 分配；真实请求只到本地 fixture-high/fixture-low 模拟模型。三个用例都没有额外分类器调用。

文档用例发现 Claude Code 会拒绝子代理直接 Write `report.md`，返回要求通过文本交接的工具错误。协作说明因此要求返回 needs_parent_write 和正文，由主会话在原授权范围内写入，随后验收；不尝试用 Bash 或改名绕过限制。最终文件内容另行核对。

所有子任务请求保留同一原问题的 session_id、prompt_id，独立 agent_id 区分执行和验收。SubagentStart/Stop 能返回代理名称和精确归属。网关只保存事件元数据和状态，不保存回答正文、证据或路径。

## 回归覆盖

- 明确执行角色不会因交接文本中的复杂词、工具错误或自己的 thinking 历史改派高级模型；验收角色固定高级。
- 主会话简单问题保留原自动路由；发生委派后优先高级模型统筹。普通 auto 行为不变，后台辅助请求不继承执行角色。
- 用户额外的 agents、系统补充说明、hooks 和权限保留；保留名称冲突与模型冲突会明确报错。会话文件权限为 0600，退出清理。
- 缺少问题 ID 时只用唯一 hook 绑定补齐；跨会话、错误问题、多个父问题均不猜测归属。
- 内容不支持、上下文超限、受保护历史来源未知以及执行请求上限阻止派发；子代理压缩继续使用自己的分支。
- hook 重复投递不重复计算结果；模型报告不写人工反馈。价格未知保留未知，用量不完整不补零。
- `go test -race ./...`、`go vet ./...`、本机编译及 Windows amd64 交叉编译通过；Windows 运行时未实测。
- 浏览器核对阶段统计、问题级协作详情、模型自报标签和未知费用；自动刷新保留选中的问题。

## 真实试用仍需评估

真实 Opus/Kiro 与 DeepSeek 的子代理输出和工具兼容性、模型是否合理分工、交接返工次数、缓存命中、整问题总成本和最终人工验收仍需实际任务验证。子代理启动和复核有开销，不能根据模拟结果声称节省比例。执行请求上限按子代理计算，不是整问题或整会话费用预算。
